## 3．实验行为、参数扫描与对照矩阵

### 搜索起点校准

比较原起点、沿canonical20前移1项、前移2项、同块从fastest起搜和预测质量裕度校准。前移在序列首端截断，每种方案均从修正后的起点按原顺序重建锁块、放宽及回退状态。`[opinion]`

裕度校准对颜色图与Linear图的适用指标增加预测补偿。PSNR与MS-SSIM各扫描`{0、0.25、0.5、1.0}` dB，共16组，零补偿重现基线。Linear只应用PSNR补偿，法线预测补偿固定为0。补偿后的预测通过原规则选择起点，实际质量门槛使用原始值。含原起点和三种直接前移方式，去除零补偿重复后共有19种起点配置。`[opinion]`

起点预筛依次比较块大小匹配率、完整配置匹配率和较少查询次数。并列时优先更小的有效预测补偿，再优先较少前移，仍并列按矩阵声明顺序选择。零补偿与原起点归为同一配置。`[opinion]`

### 删除锁块后的跨块前瞻

将跨出已锁定块的判断移至候选测量前。要求每张图最终Blocksize、Quality、选择原因、严格质量判定和ASTC字节与原V3一致，查询轨迹只减少对应末尾跨块查询，单列节省的编码、解码和质量计算时间。`[opinion]`

### exhaustive门控

门控余量扫描`{0、0.5、1、2}` dB。实际搜索准备测量某大图候选的exhaustive时，若该块满足当前锁块状态，且模型预测其MS-SSIM低于实际门槛减去余量，则先测量同块thorough。模型预测取冻结模型原始输出，起点校准补偿只用于起点选择。`[opinion]`

thorough严格达标则接受，只有PSNR达标则允许该实验返回同块放宽结果，PSNR未达标则继续原exhaustive路径。该探测覆盖直接从exhaustive起搜的情况。已测thorough在同次搜索内复用，最终输出使用实际测得的候选。`[opinion]`

逐次记录门控触发、探测成本、是否跳过exhaustive以及实际质量。开发集评分额外核查被跳过的exhaustive能否严格达标，并报告PSNR、MS-SSIM连续变化。门控放宽结果保留大图放宽语义及独立门控审计字段，组合实验可继续执行解锁。`[opinion]`

门控预筛优先保留相对同批V3严格质量回退为0的配置，再依次比较严格通过率、较少exhaustive查询和较少总查询，仍并列则优先较大门控余量。若四种余量均引入严格质量回退，保留全部负结果，组合中的门控取关闭，并记录配置合并关系。`[opinion]`

### 受限大图解锁

仅处理原搜索或门控得到的严格未通过大图放宽结果。相邻块按12→10、10→8、8→6单次尝试，6×6保留原结果。按实际尺寸计算mip0 payload，下一块超过解锁前锁块结果的1.5倍时保留原结果。字节预算采用`2 × 新payload ≤ 3 × 解锁前payload`的整数比较。`[verified: 用户确认单图体积最多增加50%]` `[opinion: 算法约定]`

预算允许时，下一块按原Quality顺序实际搜索，找到严格合格结果才替换，否则保留原结果。解锁补救搜索以真实严格质量为准，逐图记录所有额外查询、预算阻止事件和最终增量字节。最终报告同时提供相对锁块结果与相对V3结果的payload比例。`[opinion]`

### 真实编码对照

先离线完成参数扫描，再固定起点和门控参数。查询次数作为预筛依据，时间收益依据真实运行测量。正式运行九组对照，去重需同时满足有效配置、最终决策、查询轨迹和门控／解锁行为一致，并保存别名映射。`[opinion]`

| 对照名称 | 启用改动 |
|---|---|
| 当前V3 | 原模型、原起点、原搜索。`[opinion]` |
| 删除前瞻 | 仅提前检查锁块退出。`[opinion]` |
| 起点校准 | 仅选定起点方式和补偿参数。`[opinion]` |
| exhaustive门控 | 仅选定门控余量。`[opinion]` |
| 大图解锁 | 仅1.5倍payload预算解锁。`[opinion]` |
| 起点与执行优化组合 | 起点校准＋删除前瞻。`[opinion]` |
| 门控组合 | 起点校准＋删除前瞻＋exhaustive门控。`[opinion]` |
| 质量提升组合 | 起点校准＋删除前瞻＋大图解锁。`[opinion]` |
| 完整组合 | 起点校准＋删除前瞻＋exhaustive门控＋大图解锁。`[opinion]` |

### 小样本闭环与边界检查

检查首候选截断、零补偿基线、同块fastest、起点跨块、exhaustive直接起搜、门控预测误判、thorough未过PSNR、float32阈值边界、1.5倍payload边界、6×6终点、解锁失败和候选缓存复用。`[opinion]`

离线轨迹与真实查询、选择及回退须一致，最终ASTC重新解码复算质量。删除前瞻逐图核对ASTC字节和结果一致。32图闭环通过后扩展到完整1000图，模型保存身份及运行前后参数／buffer摘要复核一并归档。`[opinion]`

执行核查使用对应计时单元保存的实际新预测进行重放，冻结批量预测存档用于参数选择及差异参照。逐图模式与批量模式可能因门槛附近的预测数值变化而产生不同起点，各自记录并审计，严格质量回退与同scope、mode和repeat的V3实际结果配对。已发现的开发图901加入32图闭环，四种输入模式均覆盖。`[verified: runtime-mismatch901-diagnosis.json；smoke32-v3-artifact-audit.json]` `[opinion: 执行核查口径澄清]`
